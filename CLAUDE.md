# REDLINE // 1989

Fast-paced 2D top-down zombie action game. Godot **4.7.2** (GDScript, `gl_compatibility`), exported for Web,
hosted on Firebase Hosting (project `project-dweller`, site `redline-1989`, live at https://redline-1989.web.app).

## Git workflow (strict — follow in every session)

| Branch | Purpose | Rules |
| --- | --- | --- |
| `main` | Production. Mirrors the live site. | **Never commit directly.** Only merge tested releases from `develop`. |
| `develop` | Integration. Everything developed and verified so far. | **Never build features directly on it.** Only receives merges from `feature/*`. |
| `feature/<feature_name>` | All new features, fixes and experiments. | Always branch off `develop`. |

Procedure for any change:

1. `git fetch origin && git checkout develop && git pull origin develop`
2. `git checkout -b feature/<feature_name>`
3. Do the work; run all checks below locally until they pass. Push the feature branch (CI runs checks only, no deploy).
4. `git checkout develop && git merge --no-ff feature/<feature_name>` — resolve any conflicts cleanly, re-run the checks.
5. `git push origin develop` (CI deploys to the `develop` preview channel).
6. `main` is only updated by merging `develop` after the `develop` preview has been verified by the user. Do not
   touch `main` unless the user explicitly asks for a release.

## Checks (must pass before merging into `develop`; CI runs the same on every branch/PR)

```sh
godot --headless --import
godot --headless --quit                       # script parse/load check
godot --headless -s tests/smoke_test.gd       # headless simulation test
mkdir -p web && godot --headless --export-release "Web" web/index.html && test -f web/index.wasm
cp web_template/manifest.webmanifest web_template/icon-192.png web_template/icon-512.png web/
```

If art sources changed, first run the matching tool (see the art pipeline table below).

Treat any `SCRIPT ERROR` / `Parse Error` in the output as a failure even when the exit code is 0.

## CI / deploy (`.github/workflows/deploy.yml`)

- Checks run on pushes to `main`, `develop`, `feature/**`, on PRs targeting `develop`/`main`, and on manual dispatch.
- Push to `develop` → Firebase preview channel `develop`. Push to `main` → `live`. Feature branches never deploy.
- Requires the repo secret `FIREBASE_SERVICE_ACCOUNT`.
- `web/` and `.godot/` are build output and git-ignored. Never commit them.

## Art pipeline: 3/4 oblique pixel art + procedural lighting/FX

The game is drawn in a 3/4 oblique top-down view: you see characters' faces, bodies and legs, and props have a
top face and a front face. All of it is generated by scripts in `tools/` and committed; CI runs none of them.

| Tool | Output | Used for |
| --- | --- | --- |
| `tools/draw_characters.py` | `assets/sprites/chars/sheet_characters_v2.png` (64x64 cells) | player and infected animations |
| `tools/draw_props.py` | `assets/sprites/props/sheet_props_v2.png` + `scripts/prop_atlas.gd` | furniture, glass, signs, alarm lamps |
| `tools/draw_weapons.py` | `assets/sprites/weapons/*.png` | held weapon (side view), HUD icon, floor pickups |
| `tools/slice_sheets.py` | `assets/sprites/floors/*.png` (also chars/props, now unused) | floor textures, from `assets/raw/` |

- The three `draw_*` tools paint through the Atelier CLI (https://github.com/marmikshah/atelier). They share
  `tools/_atelier.py`, a small renderer: forms are lit from the upper left, quantised onto a colour ramp with
  ordered dithering, outlined, then given detail passes. Characters are posed skeletons, so an animation is a list
  of poses. Use the project skill `atelier-pixel-art` for the install, drawing rules and wiring steps.
- Character and prop sheets hold **2 pixels per world pixel** (a map cell is 32 sheet pixels); characters are drawn
  at `Fx.ART_SCALE`. Floors and weapons hold 4 pixels per world pixel.
- Sheet layout is a contract between a tool and the game: character rows/frames with `ANIMS` in `scripts/fx.gd`;
  prop rectangles and footprints with the generated `scripts/prop_atlas.gd` (never edit that by hand).
- Characters face right in the sheet; the game flips them (`flip_h`) and rotates only the weapon arm.
- **Fallback:** every texture resolves through `Fx.tex()` / `Fx.img()`, which load the file if it exists and
  otherwise generate a stand-in with the same layout, so the game and CI work with any sheet missing.
- All tools are deterministic and exit 0 when their input or tool is missing. Re-run them when their source
  changes and commit the output plus the `.png.import` files Godot creates. Never hand-edit `assets/sprites/`.
- `assets/raw/`, `assets/cc0/` and `web_template/` carry a `.gdignore` so Godot does not import them.
- Unused but still in the repo: the top-down character/prop sprites from `slice_sheets.py` and the Kenney CC0
  pack (`tools/import_cc0.py`, `assets/cc0/`, `assets/sprites/cc0/`).

Depth and lighting (`world.gd`):

- The world node is Y-sorted. Actors sit on their feet; a furniture piece is one sprite standing on the bottom
  edge of its footprint; walls with floor behind them get a cap that hides the feet of whoever stands there.
  The floor, gore and self-lit wall decoration use negative `z_index` so they never sort against actors.
- Dark `CanvasModulate` ambient (`#1a1528`), `PointLight2D` room lights, strobing alarm lamps, prop glows,
  flashlight cone, muzzle flash and explosions. Neon trim and signs are unlit (`light_mask = 0`, modulate that
  cancels the ambient). FX (tracers, slashes, popups) draw on a `CanvasLayer` that follows the viewport.
- **Lighting, glow, gore, particles and all audio stay procedural** (`fx.gd`).

## Display and web shell

- Base canvas 1920x1080, stretch `canvas_items` + `expand`: wider phones (20:9, 21:9) get more width, never bars.
- World units are unchanged (16px tiles); `Camera2D` zoom is 3.6. The floor is baked at 3 texture pixels per world
  pixel. Text drawn in the world is drawn at 4x size and scaled down to stay sharp.
- Portrait and landscape are both supported. HUD and touch controls are laid out in units (the SHORT screen side
  is 360 units; `W` x `H` units overall) by `Hud.layout()` / `Controls.layout()` and anchored to the corners; never
  use fixed pixel positions there. The smoke test checks both layouts for overlap on several screen shapes.
- The camera zoom also follows the short side, so both orientations show the same amount of room.
- Touch scheme: MOVE stick (left), HIT/FIRE (hold to attack, drag to aim, otherwise auto-aim), KICK/EXEC, DASH.
  Presses are buffered for 100ms in `controls.gd`; gameplay must only `take()` a press when it can act on it.
- `web_template/custom_shell.html` is the export shell (Godot's default plus the fullscreen toggle, which is sized
  in the same units and sits in the slot `Hud.layout()` keeps free top-right, and PWA tags).
  `manifest.webmanifest` and the icons are copied into `web/` by CI after the export; do the same locally.

## Project layout

- `project.godot`, `export_presets.cfg` (preset `Web`, no threads), `main.tscn` (root node + `scripts/main.gd`).
- `scripts/main.gd` — run lifecycle: floor build, restart (same seed), score/combo, win/lose state.
- `scripts/layout.gd` — pure data: hand-made room chunks stitched into a tile grid from a seed (deterministic).
- `scripts/world.gd` — bakes floors and wall faces, builds Y-sorted props and wall caps, lights, collision, doors
  (kicked doors fly), glass, pickups, A* grid, raycasts, noise propagation.
- `scripts/player.gd`, `scripts/enemy.gd` — actors. `scripts/controls.gd` — touch sticks/buttons + keyboard/mouse.
- `scripts/fx.gd` — sprite loading with procedural fallbacks, `AudioStreamWAV` sounds, decals, particles.
  `scripts/hud.gd` — HUD.
- `scripts/prop_atlas.gd` — generated table of the props sheet.
- `tools/` — art generators (see above). `assets/` — raw sheets, the CC0 pack and generated sprites.
  `web_template/` — HTML shell, PWA manifest, icons.
- `tests/smoke_test.gd` — headless test; drives the game through `controls.override`.

## Conventions

- Scripts reference each other with `preload` constants, not `class_name` or autoloads (keeps `-s` test runs working).
- 16px tiles, nearest filtering. Mobile-first: every action must be reachable by touch.
- Restart after death must stay under 0.2s (asserted by the smoke test) — keep per-floor build work cheap and cached.
- Each room is its own floor sprite and decal canvas so no canvas item exceeds the 2D light-per-item limit; keep
  that split when adding lit content.
- New gameplay behaviour gets an assertion in `tests/smoke_test.gd`.
